# Orvane Works — Deployment & Operations Manual

This guide outlines the exact production setup, DNS configuration, Supabase Auth rules, Resend SMTP integration, and deployment execution steps.

---

## 1. Supabase Auth Configuration Settings

Navigate to **Supabase Dashboard -> Authentication -> URL Configuration**:

- **Site URL**:
  ```
  https://orvaneworks.vercel.app
  ```
  *(Or your production custom domain if assigned)*

- **Redirect URLs (Allow list)**:
  ```
  http://localhost:3000/**
  https://*-orvaneworks.vercel.app/**
  https://orvaneworks.vercel.app/**
  https://yourdomain.com/**
  ```

Navigate to **Supabase Dashboard -> Authentication -> Email Templates**:
- **Enable email confirmations**: `ON` (Checked)
- **Confirm signup email template**: Points to `{{ .SiteURL }}/login`

## 2. Resend Custom SMTP for Supabase Auth

To route all Supabase authentication emails (account confirmations, magic links, password resets) through Resend under your verified domain:

1. In the **Resend Dashboard** (https://resend.com/api-keys), generate an API Key with `Full Access`.
2. In the **Supabase Dashboard**, navigate to **Project Settings -> Authentication -> SMTP Settings**.
3. Enable **Custom SMTP** and enter the following parameters:
   - **Sender email**: `hello@yourdomain.com` (or `orvaneworks@gmail.com` via verified sender)
   - **Sender name**: `Orvane Works`
   - **Host**: `smtp.resend.com`
   - **Port**: `465` (SSL) or `587` (TLS)
   - **Username**: `resend`
   - **Password**: `<YOUR_RESEND_API_KEY>`

## 3. Domain DNS Authentication Records (SPF, DKIM, DMARC)

Add the following DNS records with your domain registrar (Cloudflare, Namecheap, GoDaddy, etc.) to guarantee 100% email deliverability:

### A. SPF Record
- **Type**: `TXT`
- **Name/Host**: `@` (or root domain)
- **Value**: `v=spf1 include:amazonses.com ~all`
- **TTL**: `3600` (or Auto)

### B. DKIM Records
Add the three DKIM CNAME records generated by your Resend Domain settings:
- **Type**: `CNAME`
- **Name/Host**: `resend._domainkey` (and corresponding selectors)
- **Value**: `<unique-subdomain>.dkim.resend.com`
- **TTL**: `Auto`

### C. DMARC Policy Record
- **Type**: `TXT`
- **Name/Host**: `_dmarc`
- **Value**: `v=DMARC1; p=none; rua=mailto:orvaneworks@gmail.com; pct=100; sp=none; aspf=r;`
- **TTL**: `3600`

## 4. Sequential Production Deployment Commands

Execute these commands in your local terminal in this exact sequence:

### Step 1: Link your Remote Supabase Project
```bash
npx supabase login
npx supabase link --project-ref <your-supabase-project-id>
```

### Step 2: Push Database Migrations
Pushes all 8 schema migrations (including initial schema, RLS, rate limiting, auth triggers, payments, site settings, quotes/orders sequence, and storage buckets):
```bash
npx supabase db push
```

### Step 3: Run the Demo Clean-up Script (Only if Demo Data was Previously Seeded)
In your Supabase Dashboard -> **SQL Editor**, open:
[`scripts/cleanup-demo.sql`](../scripts/cleanup-demo.sql)
Review the transaction and click **Run**. (It deletes demo orders ORV-2026-0001/0002, demo email domains, and placeholder packages in a single rollback-safe transaction).

### Step 4: Bootstrap the Founding Administrator
Run the admin bootstrap script with your desired admin email:
```bash
ADMIN_EMAIL="orvaneworks@gmail.com" npm run admin:create
```
*This elevates the profile in `public.profiles` to `admin` and dispatches a secure password setup link to your inbox.*

### Step 5: Deploy to Vercel
Push your repository to GitHub / GitLab, connect it to Vercel, and configure the Environment Variables in the Vercel Dashboard matching `.env.example`.
Build Command: `next build`
Output Directory: `.next`
Node.js Version: `20.x`
